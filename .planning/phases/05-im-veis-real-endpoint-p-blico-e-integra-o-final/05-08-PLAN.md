## Planner assumptions (RESEARCH open questions resolved here)

- **A-01 (Open Question 1, reversible):** `Cidade` gains `final int? id` outside `==`/`hashCode`; `CidadeModel.paraEntidade()` passes it; prefs persist `nome|uf|id` and still read `nome|uf`; remote datasources (05-09, 05-12) throw a clear `FormatException` when the city has no id.

<assumption_delta_decision>
- Primary noun: `Cidade` identified by its natural key nome+uf (`chaveNatural`).
- Decision: add-alongside — the API id is added as a routing attribute next to the natural key, outside equality.
- Rationale: prefs, session filters and geocoding matching all key on nome+uf; the API id only builds URLs.
- Accepted debt: two identifiers coexist. A later promote would be forced if the API ever serves two cities with the same nome+uf, or if the app starts addressing cities by id (deep links).
- Invariant test (accepted, Task 2): every city of the captured `cidades.json` round-trips through the repository's save/read with the same id and the same equality.
</assumption_delta_decision>
